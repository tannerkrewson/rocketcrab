# Runtime sandbox spike (F4)

**Status: TEMPORARY spike — reference material.** The real runtime is built
in `apps/runtime` by U3. This spike exists to answer the F4 risk question:
_can local pasted HTML run on a separate static origin with useful browser
capabilities while remaining isolated from the Nova application?_

It is intentionally **not** part of the npm workspace (`spikes/*` is outside
`workspaces`), so it cannot break the main build. Findings and the capability
matrix live in `docs/testing/` (committed); the physical-device pass is the
human checklist in `docs/testing/physical-device-checklist-f4.md`.

## What it is

Three HTTPS origins (each a Vite dev server with a throwaway self-signed cert,
generated by `npm run gen-certs`):

| App        | URL                      | Role                                                          |
| ---------- | ------------------------ | ------------------------------------------------------------- |
| `host/`    | `https://localhost:5273` | origin A — the "Nova app" shell                               |
| `runtime/` | `https://localhost:5274` | origin B — isolated execution origin                          |
| `evil/`    | `https://localhost:5275` | origin C — unrelated page that tries (and fails) to bootstrap |

The host embeds the runtime in a cross-origin iframe and bootstraps it with an
**exact-origin `postMessage`** that transfers a dedicated **`MessageChannel`**.
Games are sent over the channel as HTML strings and executed inside a
same-origin **sandboxed iframe on the runtime origin** (`sandbox="allow-scripts
allow-same-origin"`, plus permission delegation via the `allow` attribute).
The host keeps heartbeat, soft reload, hard restart, and an **Emergency Stop
button that lives outside the frame**.

Origins are derived from `location` (port swap), so the same code works on
`localhost` and on a LAN IP for physical-device testing.

## Run it

```sh
npm install
npm run dev          # starts host :5273, runtime :5274, evil :5275
```

Open `https://localhost:5273` (accept the self-signed cert warning). Buttons:
**Load hello game** (capability probe), **Load malicious game** (isolation
probe), **Reload game (soft)**, **Restart runtime (hard)**, **🛑 Emergency stop**.

## Automated validation

```sh
npm run test:e2e    # 16 Playwright tests, all HTTPS, all origins
```

Covers the capability matrix (inline scripts, inline/remote ESM, fetch,
remote image, canvas 2D, WebGL, Web Audio after a gesture, WebSocket, file
input, clipboard, camera/mic with fake devices, device orientation, page
visibility, reload/destroy) and the security validation (game cannot reach the
host DOM/storage/cookies/top navigation/stop control, wrong-origin and
malformed bootstrap messages rejected, runtime origin holds no secrets,
CPU-exhaustion recovery).

## Key findings

See `docs/testing/runtime-sandbox-findings.md`. The short version:

- The two-origin model works and the isolation boundary holds (all host-origin
  access blocked with `SecurityError`).
- The game is same-origin with the **runtime page** itself (documented
  ADR-0008 / B5) — the runtime page must remain secret-free by design.
- Camera/mic/clipboard require permission delegation on **both** iframes.
- WebGL/audio work in a sandboxed game frame (headless needs SwiftShader flags).
- An infinite-loop game freezes the whole tab in this headless shell because
  cross-origin process isolation (OOPIF) is unavailable there — **shell
  survival under CPU exhaustion must be verified on physical browsers**; this
  is the F4 physical-device pass.
